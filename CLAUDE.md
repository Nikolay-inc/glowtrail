# Проект: Glowtrail — мобильная и веб-головоломка

- Стек: TypeScript, Phaser 3, Vite, Capacitor 7 (iOS и Android; Capacitor 8 требует Node 22).
- Игра должна работать в мобильном браузере: касания, вертикальный экран 9:16, масштабирование под любой экран.
- Без внешних картинок: на этапе прототипов вся графика — простые фигуры и цвета в коде.
- Уровни храним в JSON, логику игры держим отдельно от отрисовки, чтобы её можно было тестировать.
- После изменений запускай сборку и тесты; не оставляй проект в нерабочем состоянии.
- Отвечай и комментируй на русском.

## Коммиты

- Сообщения коммитов — только на английском.
- Формат: `<type>: <short summary>`, где type — `feat` (новая возможность) или `fix` (исправление). Примеры: `feat: add hint button`, `fix: stash tap on empty slot`.
- Заголовок короткий (до ~60 символов), в повелительном наклонении, без точки в конце. Подробности при необходимости — в теле коммита, тоже на английском.

## Команды

- `npm run dev` — локальный сервер (http://localhost:5173, `?level=N` открывает уровень сразу)
- `npm test` — тесты Vitest (`tests/`)
- `npm run verify` — таблица метрик по всем уровням; проверяет решаемость, звёзды, колоды облегчения, актуальность метрик, светлячков, туман «без угадывания» (`fogFair`), пороги звёзд (2★ < 3★ на всех уровнях с колодой), не меньше 4 решений у средних и «сложнее» (кроме испытаний, `MEDIUM_MIN_ROADS`) и кривую (1–10 — таблица в `scripts/verify.ts`, 11–60 — планы миров `src/levels/curve.ts`, «пила» в десятках, рост рейтинга по десяткам мира). `--world forest` — только уровни мира, `--md` — таблица в Markdown
- `npm run ease` — пересчитать колоды незаметного облегчения (`easeDecks`) и метрики сложности (`metrics`) в JSON; запускать после любого изменения уровня
- `npm run gen -- --count 300 --size 5x6 --features lantern,rock,water,firefly,jump,turnbridge,fade,ring,fog,shadow,ice,drift,wind --seed N [--reserve 2-7] [--goal fireflies|escape|signals] [--min-roads 10] [--max-rating 3]` — генератор кандидатов в `generated/` (в git не идёт; воспроизводится по seed). Отбрасывает нерешаемые, с 1 решением, «скучные» (тупиков < 12%), требующие «отложить», с недоступными светлячками, слишком тяжёлые для решателя (> 60 000 состояний), туман с угадыванием (`fogGuess`) и те, где новый элемент не нужен (без прыжков не решается; без поворотного моста не решается; без колец не решается; гаснущий фонарь и тень отнимают решения; под туманом на старте спрятан камень или вода; сугроб не нужно растапливать; без льда или ветра то же число решений; у «Сигнальных огней» порядок не отнимает решений). Огни (`--goal signals`) — 2–4 костра не у края, номера чаще от ближнего к старту. Тень (`shadow`, у `escape` — всегда): число ходов подбирается по колоде (`shadowFor`: самое строгое решаемое + 0–2)
- `npm run sim-economy` — экономика на три главы (`src/core/economyModel.ts`): три профиля (слабый 1,8★/40%, средний 2,4★/65%, сильный 2,9★/90%), каждый без перепрохождений и с 15 мин перепрохождений и заданий в день; таблица цен, «когда что доступно» (доля построек, слотов украшено / вариантов куплено, гардероб Lumo и стили поля — куплено / награды, расцветы за испытания, свет в конце главы; названия — из `ru.json`), где «впритык», сколько дней добирать. Падает, если не выполнены цели: средний без перепрохождений — 85–90% построек и первых улучшений к концу каждой главы, слабый — ≥ 75%; гардероб среднего 3–4 вещи к главе 1 и 10–13 к главе 3 (13 — с двумя наградами Горного города; с 15 мин — 1,4–2,4×), первая вещь ≤ 20 мин; стили поля (фонари, дороги, арки) среднего 1–2 к главе 1 и 5–6 к главе 3; свет в конце главы ≤ 30 (с 15 мин ≤ 60); «хвост» с 15 мин — все третьи уровни, все улицы и по украшению в каждом слоте ≤ 45 дней; пауза между целями в первый час ≤ 5 мин у слабого и среднего. Тест проверяет то же самое
- `npm run i18n-check` — ключи во всех языках, подстановки, неиспользуемые ключи, русский текст в коде; затем Playwright открывает все экраны и окна (`src/debug/audit.ts`, `?audit=1`) на псевдо-языке qps на 375x667 и ищет надписи за контейнером/кнопкой/окном/экраном, надписи с внутренним id (постройка, район, вещь, набор, украшение) вместо названия и ключи без перевода (`missingKeys`); на карте деревни — перекрытия (`villageOverlaps`: подписи и ценники не под соседними постройками и лопастями, слоты и знаки улиц — ни на постройках, подписях, Lumo и друг на друге; подписи — вторым проходом на ru и en, в qps они искусственно длинные) и касания (Playwright жмёт на рисунок и подпись мельницы, колодца, маяка, обсерватории на 375x667 и 390x844 — должно открыться окно постройки); скриншоты — `artifacts/i18n/`. Флаги `--static`, `--lang ru|en|uk|qps`, `--size 390x844`, `--only map,village`. В CI
- `npm run pick` — подбирает уровни из кандидатов под план мира и пишет `src/levels/<мир>/NN.json`: без флага — «Долина» 11–30, `--world forest` — «Туманный лес» 31–60, `--world peaks` — «Ледяные вершины» 61–90 (`--dry` — только показать, `--only 14,20` — перевыбрать эти номера)
- `npm run fireflies -- --world peaks [--plan 1:2,3:2,7:2,10:4] [--only 61,63] [--dry]` — ставит необязательных светлячков на пустые клетки решения (без «отложить») на 1-м, 3-м, 7-м уровне десятка и испытании, если светлячков там ещё нет; потом `npm run ease` и `npm run verify`
- Редактор уровней: `npm run dev`, затем `http://localhost:5173/?editor=1` (только при разработке, в сборку не попадает)
- `npm run build` — проверка типов и сборка в `dist/` для Pages (base `/glowtrail/`)
- `npm run build:app` / `cap:sync` / `cap:ios` / `cap:android` — сборка для приложения (base `./`, mode `app`, ключи из `.env.app`) и открытие нативного проекта
- `npm run ios:strings` — тексты Info.plist на всех языках из i18n (`ios/App/App/<язык>.lproj/InfoPlist.strings`: текст запроса ATT, ключ `att_description`); тест сверяет файлы с переводами
- `npm run icons` — иконка и заставка: рисунок в `scripts/icon-art.ts` (силуэт Lumo с фонарём на холме, ореол, светящаяся тропа, светлячки), `scripts/make-icons.ts` собирает `assets/*.png` (иконка, слои адаптивной иконки Android — Lumo в безопасном круге, заставка с названием в небе), `public/favicon.svg` и `public/apple-touch-icon.png`; `capacitor-assets` нарезает размеры iOS и Android
- Деплой: пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) → https://nikolay-inc.github.io/glowtrail/

## Правила механики (как реализовано)

- Плитки относительны направления дороги. Каждая плитка занимает клетку(и) впереди конца дороги; поворот занимает клетку впереди и разворачивает дорогу.
- Мост ставится только на воду, вода проходима только мостом. «Прямо x2» не перепрыгивает препятствия.
- «Прыжок» (`jump`, с уровня 15): перелетает через одну клетку (камень, воду, фонарь, мост, свою дорогу — не арку) и встаёт на следующую; приземлиться можно только туда, куда встала бы обычная плитка. Перепрыгнутая клетка на дорогу не попадает: фонарь не зажигается, светлячок не собирается.
- Поворотный мост (`-` горизонтальный, `|` вертикальный на старте, с уровня 21): после каждой поставленной плитки поворачивается на 90° («отложить» и обмен время не двигают). Пройти можно только вдоль моста и только прямо (повернуть на мосту нельзя, мост-плитка не нужна). Мост под дорогой больше не крутится. Следующее положение показано полупрозрачно.
- Гаснущий фонарь (цифра `2`–`9`, с уровня 25): после зажигания горит N ходов (число на табличке уменьшается с каждой плиткой); последняя из N плиток ещё может войти в арку. Погас до арки — снова не зажжён, пройти через него второй раз нельзя → поражение.
- Цель уровня (`goal`): `classic` — арка и фонари; `fireflies` — арки нет, победа при сборе последнего светлячка (с уровня 18); `escape` — «Побег» (с уровня 51): арка открыта сразу, дойти до неё, пока тень не догнала (фонари не обязательны — задерживают тень). Карточка цели, строка цели и экран «Почти!» меняются под цель.
- Грибные кольца-телепорты (`a`/`b` — пары, до 2 на уровне, с уровня 31): плитка, вошедшая в кольцо, выходит из парного в том же направлении (поворот на кольце поворачивает после выхода, «прямо x2» продолжает от парного, прыжок перелетает кольцо, не входя). Оба кольца пары попадают на дорогу (`PlacedCell.portal`: in/out), второй раз не войти. Lumo тает в искрах и появляется у парного.
- Туман (`fog: true`, с уровня 35): скрыто всё, кроме клеток в радиусе 1 (по квадрату) от дороги и 2 — от зажжённых фонарей; обсерватория +1/+1/+2. На правила не влияет — только на видимость; verify/тест/генератор требуют `fogFair`.
- Тень (`shadow: N`, с уровня 41; число — на старте): появляется на старте через N ходов, затем каждый ход пробегает 2 клетки дороги (`SHADOW_SPEED`; с 1 клеткой не догнала бы никогда — дорога растёт минимум на клетку за ход). Через кольцо — скачком. Зажжённый фонарь — задержка на 1 ход (копится), травница — 1/2/3 раза за уровень стоит на месте, когда вот-вот догонит (`charms`). Догнала конец дороги — поражение «Тень настигла» → «Почти!»; на победном ходу победа важнее. Состояние — в `TimeState.sh` (`len`, `pos`, `wait`, `charm`), в ключе решателя — расстояние, задержка, заряды; в игре — проигрыш по дороге (`shadowOf`), `lossReason`. Строка цели — «через N» / «N кл.».
- Лёд (`=`, с уровня 61): закончил ход на льду — Lumo скользит дальше по направлению дороги, пока не встанет на не-ледяную клетку; камень, вода, край поля, своя дорога, нерастаявший сугроб, поперечный поворотный мост, закрытая арка останавливают на последней ледяной. Клетки скольжения — дорога того же хода (`PlacedCell.forced: 'ice'`), фонари и светлячки по пути зажигаются/собираются, в открытую арку можно въехать. Прыжок, «прямо x2» — то же правило по последней клетке. Предпросмотр рисует голубой луч до точки остановки.
- Сугроб (`*`, с уровня 65): непроходим, как камень, пока рядом (по стороне) не горит фонарь (`driftMelted` — фонарь на дороге, в том числе этого хода); растаявший — обычная клетка. Прыжок перелетает нерастаявший. Генератор ставит сугробы рядом с фонарями и требует, чтобы без таяния уровень не решался.
- Ветер (`^ > v <`, с уровня 71): закончил ход (и скольжение) на клетке ветра — сдвиг на клетку по стрелке, если там не препятствие; дорога поворачивает по ветру (`forced: 'wind'`), на льду скольжение продолжается. Проход по ветру внутри хода («прямо x2») не сдвигает. До 81-го — не больше одной цепочки «ветер → лёд» (`windIceChains`; verify, тест, pick).
- Цель «Сигнальные огни» (`goal: 'signals'`, костры `A B C D` — номера 1–4, с уровня 81): костёр загорается, когда дорога проходит или встаёт на него, только если горят все предыдущие (`firesLit`); не тот по счёту — плитка не встаёт (`reason: 'fireOrder'`, `Placement.fire`), табличка мигает номером, Lumo говорит «Сначала костёр N» — это не проигрыш. Арка открыта, когда горят все костры и фонари (число на замке — `lanternsLeft` вместе с кострами); гаснущие фонари у `signals` гаснут, как у `classic` (`goalNeedsLanterns`). Огни светятся сквозь туман.
- Всё это — в `placeTile` (`src/core/tiles.ts`): решатель, геометрия, генератор, подсказки, fogFair и игра получают механики сами; направления клеток дороги — из `PlacedCell.din` (ветер поворачивает дорогу посреди хода).
- Выход закрыт, пока дорога не прошла все фонари; «прямо x2» не может пройти сквозь выход.
- Лоток — 3 верхние плитки колоды; освободившийся слот добирается из колоды; рядом мелко видно следующие 2 плитки.
- Слот «отложить» на одну плитку. Тап по пустому слоту убирает туда крайнюю левую плитку лотка, тап по занятому — меняет её с крайней левой. Перетаскивание: плитку лотка на слот — отложить/обменять; отложенную на плитку лотка — обмен, вверх на поле — поставить. Отмена — 1 раз за уровень.
- Поражение — нет ни одного осмысленного хода (отложить считается ходом, только если в колоде остались плитки).
- Звёзды: пороги `stars.two` / `stars.three` — сколько плиток осталось; 3 — от (макс. остаток − 1), 2 — от половины макс. остатка (вниз). Формула — `starThresholds`, verify сверяет JSON с ней.
- Кривая сложности: размер поля, запас (плиток сверх минимума) и число решений. Новые элементы — по одному, после сложного уровня — лёгкий.
- Метрики (`src/core/difficulty.ts`): решений (до 500), минимум плиток, запас, доля тупиковых ходов (случайные допустимые ходы по выборке 600, детерминированно), рейтинг 1–10 = 1 + тупики (до 4) + мало решений (до 2, на коротком пути меньше) + малый запас (до 1,5) + длина пути (до 1,5) — `ratingOf`.
- Уровни-знакомства (первая встреча механики: 11, 15, 18, 21, 25 — `intro` в плане) и все «лёгкие» — рейтинг ≤ 3 и решений ≥ 10 (`mustBeEasy`; verify — ошибка, тест, pick отбирает только такие).
- Мир «Туманный лес» (`src/levels/forest`, id `forest-01…30`, номера 31–60, открывается после уровня 30): 31–34 кольца, 35–38 туман, 39 передышка, 40 испытание; 41–45 тень, 46–48 кольца + туман, 49 передышка, 50 испытание; 51–55 «Побег», 56–58 сочетания с механиками долины (кольца + прыжок, тень + поворотный мост, туман + гаснущий фонарь), 59 передышка, 60 — босс (побег через туман с кольцами). Знакомства (31, 35, 41, 51), лёгкие и передышки — рейтинг ≤ 3, решений ≥ 10. Рейтинг растёт по десяткам примерно с 3 до 7. Карточки правил «Грибные кольца», «Туман», «Тень», «Побег» (лесное поле). Палитра леса: бирюзово-фиолетовые сумерки, ели-силуэты (`addBackground({ forest })`), поле — мох, светящиеся грибы, туман плывёт, капли; музыка `forest`. Карта — одна тропинка через оба мира, на стыке — переход в лес; сцена «Lumo входит в лес» (`ForestIntroScene`) — один раз (`progress.worlds`, событие `world_enter`).
- Мир «Ледяные вершины» (`src/levels/peaks`, id `peaks-01…30`, номера 61–90, открывается после уровня 60): 61–64 лёд, 65 сугроб и тёплый фонарь, 66–68 лёд + сугроб, 69 передышка, 70 испытание; 71–73 ветер, 74–78 ветер + лёд + поворотный мост/кольца/вода, 79 передышка, 80 испытание; 81–83 «Сигнальные огни», 84–88 огни + лёд/ветер/туман, 89 передышка, 90 — испытание «Вершина» (огни, лёд и ветер). Знакомства (61, 65, 71, 81), лёгкие и передышки — рейтинг ≤ 3, решений ≥ 10; средние и «сложнее» — ≥ 4; 2–3 решения — только у испытаний. Карточки правил «Лёд», «Сугроб и фонарь», «Ветер», «Сигнальные огни» (снежное поле), строки в карточке цели, подсказки Lumo `ice`/`drift`/`wind`/`signals` при первой встрече. Палитра — бело-голубая (снег на клетках, лёд с бликом).
- Мир «Долина», 30 уровней: 1–10 — обучение (не трогаем); 11–30 — что-то новое каждые ~5 уровней: 11–14 светлячки, 15–17 прыжок, 18–20 цель «только светлячки», 21–24 поворотный мост, 25–29 гаснущий фонарь, 30 — испытание «всё вместе» (`NOVELTY` в `curve.ts`, verify и тест проверяют). В каждом десятке «пила»: 1–3 лёгкие, 4–7 средние, 8 передышка (рейтинг ≤ 3 и решений ≥ 10), 9 сложнее, 10 «испытание»; рейтинг растёт примерно с 2 до 6, испытания до 7; уровней с 1 решением нет; поле до 6x8. Прогресс хранится по id — переделка уровней его не теряет.
- Светлячки (`F`, с уровня 11): дорога через клетку собирает светлячка, собирать не обязательно (кроме цели `fireflies`), на звёзды не влияют. Счётчик в строке цели и на экране победы, лучший сбор — `progress.fireflies`. verify (и тест, и генератор) требует, чтобы все светлячки уровня можно было собрать за одну победу без «отложить» (`firefliesWithoutStash` в `analyzeLevel`). Первая встреча — карточка правила «Светлячки» (по содержимому уровня, `rulesFor`).
- Формат уровня: `grid` — строки поля (`.` пусто, `#` камень, `~` вода, `L` фонарь, `E` выход, `S` старт, `F` светлячок, `-`/`|` поворотный мост, `2`–`9` гаснущий фонарь, `a`/`b` грибные кольца — по два, `=` лёд, `*` сугроб, `^ > v <` ветер, `A`–`D` сигнальные огни по порядку), `goal` (`classic` по умолчанию / `fireflies` — без `E` / `escape` — нужна тень / `signals` — 2–4 костра), `fog: true` — туман, `shadow: N` — тень через N ходов, `startDir` N/E/S/W, `deck` сверху вниз (плитки: straight, straight2, left, right, bridge, jump), `tutorial`: `place` (рука показывает нужную плитку) или `stash` (рука показывает «отложить»), `tip` — подсказка Lumo в начале уровня (`lantern`, `side_entry`, `stash`, `water`), `tileSet` — бесконечная колода из набора, `allowStash: false` — слот «отложить» скрыт, `night: true` — ночной уровень (затемнено только поле), `easeDecks` — колоды облегчения и `metrics` — метрики сложности (оба генерирует `npm run ease`).

## Мета-игра и экономика (Р3а)

- Монеты: первое прохождение уровня — 10 + 5 за звезду, переигровка — 5 за каждую новую звезду; ещё — награда дня и объекты деревни. Хранятся как `coinsEarned − coinsSpent`. Тратятся на прокачку и скины.
- Свет: 1 звезда = 2 света, 1 светлячок = 1 свет — по лучшему результату уровня, не хранится отдельно: `lightEarned(progress) − цена восстановленных объектов`. Переигровка добавляет только разницу. Тратится на деревню.
- Повтор уровня без улучшения — 6 → 3 → 1 → 0 монет за уровень в день (`applyReplay`, `economy.replays`).
- «Деревня 2.0» (`VillageScene`, вкладка «Деревня»; окна — `src/ui/villagePanels.ts`; рисунки — `src/ui/village.ts`, `villageDecor.ts`). Районы — свайп или стрелки у названия: «Долина» (10 построек), «Лесной квартал» за мостом (травница, обсерватория, совиная почта, грибная ферма, лесопилка, мастерская фонарей, чайная, дом лесника, мост-качели, светящееся озеро) — открывается после уровня 30 (`districtOpen`), «Горный город» (шахта, кузница, канатная дорога, хрустальная пещера, козья ферма, колокольня, горячие источники, каменный мост, звёздный храм, маяк на вершине; рисунки — `src/ui/villageMountain.ts`: камень, снег на крышах, сосульки, тёплые окна; пристройки — шале, дровяник, ларёк с чаем) — после победы или пропуска уровня 60 (`district_locked_mountain`); бонусы гор — только знакомых видов и мягкие (+5/8/10% монет, скидки 5/10/15% на улицы, украшения и гардероб, замена задания, свет за 3★ и за задания, +10/20/30% к заданию недели, «+3 плитки», ночные уровни светлее); улицы — снежная тропа → тропа с песком → брусчатка в снегу → мощёная с фонарями (`drawStreet(..., 'snow')`, `street_step_snow.*`); украшения — фонари-столбики, скамейки, ели в снегу, ледяные скульптуры (`decorType(slot, 'mountain')`, `MOUNTAIN_DECOR_ORDER`); жители — горняк, пастушка коз, горный звонарь и др. ## Цель и обучение

- Выход — арка-портал, симметричная со всех сторон, с 4 огоньками-входами; огонёк загорается, когда конец дороги рядом с этой стороны. На арке замок с числом незажжённых фонарей; при 0 замок открывается. Фонарь зажигается сразу, когда через него проходит дорога.
- В начале каждого уровня — карточка цели (`showGoalCard`): цель, фонари, светлячки и, если есть на уровне, пояснения «Гаснущий фонарь» (что значит число) и «Поворотный мост» — на каждом таком уровне, не только при первой встрече. Сама не исчезает: поле затемнено, ходы заблокированы до кнопки «Старт» (или Enter/пробел); время уровня считается с «Старт», подсказки Lumo — после. Сверху всегда строка цели (арка + фонари «зажжено/всего»).
- Карточки правил (`src/rules.ts` — сценарии, `src/scenes/RulesScene.ts` — показ; крестик/Esc закрывает сразу все): живая анимация на мини-поле настоящей логикой игры — ошибка (красный крестик) и правильное решение. «Дорога к двери» — перед уровнем 1, «Фонари» — 3, «Камни» и «Вход с любой стороны» — 4, «Река» — 8 (`RULES_BY_LEVEL`), каждая один раз (`rule:*` в `tipsSeen`). В меню «Как играть» — все карточки и «Пройти обучение с начала». Тест прогоняет каждый сценарий: неудачи действительно не встают, финал — победа.
- Звёзды (победа, карта) — `drawShinyStar`: гранёные лучи со светом сверху слева, ободок, тень, блик; пустая — тёмная «лунка».
- Фонарь стоит на тёмном постаменте с оранжевым ободком и горит белым в оранжевой рамке — чтобы не сливаться с жёлтой дорогой.
- Карточки правил по содержимому уровня (`rulesFor`): «Светлячки», «Прыжок», «Только светлячки» (`ffgoal`), «Поворотный мост», «Гаснущий фонарь» — при первой встрече. На уже пройденном (или пропущенном) уровне карточек нет (`pendingRules`), кроме режима «Пройти обучение заново».
- Кнопки (`Button`) растут под содержимое: заданная `w` — минимум, подпись с иконкой (или `buttonRichLabel`) не вылезает на любом языке; ширина — `buttonWidth`. Кнопки рядом ставим `layoutRow(buttons, cx, gap)` по фактической ширине. Карточка цели перед уровнем тоже по ширине самой длинной строки (не шире экрана — тогда строки уменьшаются).
- Круглые стрелки (назад, заново, поворот) — `arcArrow` в `src/ui/draw.ts`: кончик и основание наконечника на окружности, направление по хорде — наконечник ровно на линии.
- Иконки плиток (`drawTileIcon`): одна толщина, линия из одной точки снизу, наконечник — точно на конце линии по касательной, повороты центрированы. Превью следующих плиток — ряд у правого края колоды.

## Живое поле (BoardView)

- Палитра «Долины» — сумерки: тёмный луг и вода, сумеречное небо с чёрными холмами (`addBackground(scene, { evening: true })`). Над полем всегда полумрак (`BoardOptions.dark`, у ночных уровней гуще); дорога — лента света (сияние, тёплая полоса, яркая сердцевина, искорки), она освещает траву вокруг — Lumo несёт свет в поле.
- Украшения пустых клеток (травинки, цветы, камешки) — случайные, но стабильные от id уровня; трава колышется в `update`, прячется под дорогой. Вода — волны и блики; светлячки летают по кривым; днём изредка пролетают бабочки, над полем — тёплые искры.
- Lumo стоит на конце дороги и шагает по каждой плитке (~250 мс, подпрыгивает, фонарь покачивается; прыжок — высокая дуга), свет растекается по новой клетке огоньком на краю, с искрами и мягким «бум» (`sfx.thump`), в приложении — лёгкая вибрация на шаг (`haptics.step`). Финал — волна света по дороге зажигает фонари, Lumo входит в арку (у цели «светлячки» — светлячки кружат вокруг него).
- Серия без отмен: с 3-го хода подряд — искры по дороге (`board.sparkle`) и нарастающая нота (`sfx.streak`); отмена сбрасывает.
- Уровень 4 учит входу в арку сбоку (снизу камень, сверху край поля) — verify это проверяет.
- Первый запуск: вступление (~12 с, пропуск тапом) → уровни 1–3 с карточками правил и подсказками → карта мира → окно «Как тебя зовут?». Предложение войти — после уровня 6. В меню кнопка «Как играть» (карточки правил, оттуда же — пройти обучение заново: карточки и подсказки покажутся снова, прогресс не трогается).
- Подсказки Lumo: после первой ошибки — «назад», бездействие 15 с или 2 поражения — «подсказка», тупик — «заново», «отложить», первый поворот (иконки в лотке поворачиваются), камень, вода (на первом уровне с водой подсвечивается мост), фонарь, вход сбоку, перетаскивание. Реплика у закрытой двери — при каждой попытке и в окне тупика.
- Плитку можно перетащить на конец дороги (подсвечивается зона сброса и предпросмотр); мимо — плитка возвращается. Предпросмотр рисует настоящий изгиб дороги; на конце дороги — конус света в направлении движения.
- В логе: `tutorial_step`, `tip_shown`, `tap_place`, `drag_place`, `door_locked_attempt`, `fireflies_collected` (на победе, `fireflies`/`firefliesTotal`), `tile_jump_used`, `bridge_rotated_blocked`, `lantern_expired` (`tile` — номер плитки), `teleport_used`, `shadow_delayed` (`source`: lantern / herbalist), `shadow_caught`, `fog_revealed` (в конце попытки: `cells` открыто из `total` скрытых), `world_enter` (`world`), `ice_slide` (`cells`), `wind_push`, `drift_melted` (`cells`), `signal_lit` (`fire` — сколько горит, `total`), `fire_order_blocked` (`fire`, `need`); `start` содержит метрики уровня (`rating`, `trap`, `roads`) и `goal_type` (classic / fireflies / escape).

## Защита от застревания

- Отмена хода без ограничений: можно отменять много ходов подряд, до старта.
- Уровни 1–4 без лимита плиток (`tileSet` в JSON): плитки случайные из набора, но раздача «честная» — пока до выхода можно дойти, в лотке есть ведущая к нему плитка. Поражение только в тупике. Звёзды по отменам: 0 — 3, 1–2 — 2, больше — 1.
- Счётчик поражений подряд на уровень (`lossStreak`), сбрасывается победой.
- «Подсказка» бесплатна и без ограничений: следующая верная плитка по решателю; если из текущего положения не выиграть — предлагает откатиться к ближайшему решаемому состоянию. После 2 поражений подряд кнопка пульсирует.
- Экран «Почти!»: фонари x из y, расстояние до выхода, «+3 плитки» (уровни с колодой, 1 раз за попытку), «Отменить ход», «Заново».
- После 2 поражений подряд колода незаметно получает +2 плитки (`easeDecks[1]`, считаются заранее), после 4 — кнопка «Пропустить уровень»; пропущенный уровень отмечен в меню и остаётся доступным.
- События в логе: `hint_used`, `extra_tiles`, `auto_ease`, `level_skipped` (плюс `start`, `win`, `lose`, `abandon`, `session`).

## Сохранение и профиль

- Всё сохранение идёт через `src/save/SaveService.ts` (`load` / `save` / `update` / `reset`): один объект `{ version: 11, profile, progress, economy, log }` под ключом `glowtrail.save`. `economy` — `src/core/economy.ts` (`normalizeEconomy`), в облако уходит вместе с профилем и прогрессом; слияние — `mergeEconomy` (счётчики — максимум, покупки и деревня — объединение).
- Новые записи лога видит `SaveService.onLog` (дописанный хвост `d.log`, `newLogEntries`) — так все события уходят в Firebase.
- `progress` — по id уровня: `unlocked` (список id; уровень также открыт, если предыдущий пройден или пропущен — `isUnlocked`), `stars`, `attempts`, `lossStreak`, `skipped`, `fireflies`. В логе `level` — тоже id.
- `profile`: `playerId` (UUID, создаётся один раз — для будущей привязки облачного аккаунта), имя (до 16 символов, пусто → «Путник»), аватарка 0–7 (= надетый костюм), серия дней подряд, число подсказок. Логика — `src/profile.ts`, рисунки аватарок — `src/core/avatars.ts`.
- Имя спрашиваем мягко после первой победы на уровне 3 (`ASK_NAME_AFTER_LEVEL`), его можно пропустить. Экран «Профиль» — кнопка с аватаркой в углу карты мира.
- Хранилище подменяемое (`setBackend`): сейчас localStorage, потом облако. В тестах — `memoryBackend()`.
- Миграция цепочкой v1 → … → v11 (v11: `economy.shop` — покупки и реклама (`src/core/shop.ts`: «Без рекламы», стартовый набор, обработанные транзакции — слияние объединением, счётчики роликов и межуровневой), `progress.privacyAsked` — согласие на рекламу и ATT пройдены (настройка устройства); v10: `progress.worlds` — миры, куда игрок вошёл (сцена входа один раз), старые — `['valley']`, слияние — объединение; v9: `progress.analytics` — выбор про анонимную статистику `''`/`yes`/`no`, настройка устройства, при слиянии — локальное; v8: `economy.challenges` — награды испытаний `{ earned, bloomed }`, слияние — объединение; v7: «Деревня 2.0» — список восстановленных → уровни построек 1, `chapelDay` → счётчик `chapel`, новые улицы, украшения, уют, задания, `lightBonus`; v6: гардероб вместо скинов, сундук, часовня, повторы, оплаченные светлячки моста; v5: экономика; монеты за уже пройденные уровни задним числом, аватарки, открытые звёздами, остаются костюмами; облако старой версии — так же): v1 — старые ключи `glowtrail.progress.v1` / `glowtrail.log.v1` (не удаляются), v2 → v3 добавляет профиль, v3 → v4 переводит номера уровней 1…N в id `valley-NN` (прогресс, лог; облако старой версии нормализуется при слиянии). При изменении формата — поднять `SAVE_VERSION` и добавить шаг в `migrate`.

- Релиз (TestFlight): версия `0.1.0` из `package.json`, номер сборки — `app-build.json`, растёт при каждом `npm run build:app` (`npm run version:bump`, `scripts/app-version.ts`: не ниже числа коммитов; пишет `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` в iOS и `versionName`/`versionCode` в Android). В игре — `src/version.ts` (`versionLabel`, Vite define), внизу профиля. Подпись: команда `R457T4MLSR`, автоматическая. `ios/App/App/PrivacyInfo.xcprivacy` (UserDefaults CA92.1; почта, ID игрока, игровой контент, взаимодействие; Р4: `NSPrivacyTracking` = true — реклама AdMob с IDFA только по разрешению ATT, рекламные данные, ID устройства, история покупок), `ITSAppUsesNonExemptEncryption = NO`. `npm run ios:check` — проверка перед архивом. Пошагово — README («TestFlight»).
- Политика конфиденциальности — `site/privacy.html` (RU/EN), плагин в `vite.config.ts` кладёт её в сборку как `privacy.html` и подставляет `%CONTACT_EMAIL%` из `VITE_CONTACT_EMAIL` (локально `.env.local`, на сайте — секрет репозитория; адреса в репозитории нет). В профиле — «Отправить отзыв» (`src/feedback.ts`: письмо с версией и началом статистики, полная статистика — в буфер) и «Конфиденциальность».

- appId `com.severgames.glowtrail` (не менять), appName Glowtrail, webDir `dist`. Название в App Store — «Glowtrail: Light the Path» (задаётся в App Store Connect), под иконкой — «Glowtrail» (`CFBundleDisplayName`, `appName`, Android `app_name`); тест и `ios:check` это проверяют. Конфиг — `capacitor.config.ts`.
- `ios/` — Swift Package Manager (CocoaPods не нужен). В Capacitor 7.6 у `cap add ios --packagemanager SPM` баг с проверкой CocoaPods — обходили через `CAPACITOR_COCOAPODS_PATH=/usr/bin/true`; дальше `cap sync` сам видит `CapApp-SPM`. Info.plist: только портрет, `UIRequiresFullScreen`, светлый статус-бар. Минимум iOS 15 (Xcode 27 не собирает под 14; в `project.pbxproj` поднято вручную).
- `android/` — `screenOrientation="portrait"`, `adjustMarginsForEdgeToEdge: 'auto'` (Android 15). Статус-бар на Android не перекрывает веб-вью (`main.ts`), на iOS — перекрывает, фон игры под ним.
- Пошаговый запуск на iPhone — в `README.md`.
- `src/platform.ts` — `isNative()`, `platform()`, `WEB_URL` (ссылки из писем в приложении ведут на веб-версию).
- Весь экран: Phaser `Scale.EXPAND`, раскладка 1080×1920 ставится камерой в безопасную зону (`src/ui/viewport.ts`: `computeView` — чистая функция с тестом, `keepFitted(scene, onChange)` в каждой сцене через `addBackground`). Фон, звёзды, туман, виньетка рисуются на всю видимую область (`currentView`). Затемнения окон — `W * 4, H * 4`. Экраны с вкладками (карта, деревня, мастерская, магазин, профиль) берут опорные линии из `edgeRows(bounds)`: заголовок `topY` у верха безопасной зоны, ряд `rowY` и панель вкладок (`rowY + 40`) — вплотную к низу. На высоких экранах `stretchLayout(scene)` (в начале create уровня и меню) растягивает раскладку: верхняя панель к верху безопасной зоны, лоток/нижний ряд к низу (не больше 320 px с каждой стороны), поле уровня растёт (`maxCell: 250`); при изменении окна камера держит растянутые границы целиком. Координаты указателя — `p.worldX/worldY`.
- Запуск (`main.ts`, async `boot`): на телефоне сначала `createPreferencesBackend` (`src/save/preferencesBackend.ts`: чтение в память, запись с задержкой 400 мс, `flush()`, перенос из localStorage WebView при первом запуске), потом Phaser, `initLifecycle`, `Account.init()`; заставка прячется после первого кадра.
- `src/lifecycle.ts`: сворачивание (`appStateChange`/`pause`, в вебе `visibilitychange`) → `suspendAudio`, `SaveService.flush()`, `Account.flushSync()`, `game.loop.sleep()`, событие `app-pause`; возврат → `app-resume`. GameScene сдвигает `t0` на время в фоне. Android «Назад»: уровень → меню (`app-back`), меню → свернуть, статистика/профиль → меню.
- Supabase в приложении хранит сессию в Preferences (`account.ts`), `detectSessionInUrl` выключен.
- `src/haptics.ts`: `haptics.tap/place/error/win` — в приложении `@capacitor/haptics`, в вебе `navigator.vibrate` (`WEB_PATTERNS`). Выключатель — кнопка в меню, `progress.vibration` (по умолчанию true, при слиянии с облаком берётся локальное значение).
